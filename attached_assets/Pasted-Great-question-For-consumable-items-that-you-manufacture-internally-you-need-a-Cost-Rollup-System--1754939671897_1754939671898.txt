Great question! For consumable items that you manufacture internally, you need a Cost Rollup System where the item's cost is automatically calculated from its BOM components rather than being manually entered. Here's how to set this up:

BOM-Based Cost Calculation Setup
1. Item Cost Source Configuration
Each item should have a cost_source field with these options:

manual: Price entered manually (for purchased items)
bom_calculated: Price calculated from BOM components (for manufactured items)
hybrid: Both manual override and BOM calculation available
2. BOM Cost Rollup Logic
For items with cost_source = 'bom_calculated':

Item Cost = Sum of all BOM components + Manufacturing overhead
Where each component cost = (Component quantity × Component unit cost)
3. Multi-Level BOM Support
If your BOM contains sub-assemblies (nested BOMs):

Calculate sub-assembly costs first (bottom-up approach)
Roll up costs through all BOM levels
Handle circular references with proper validation
4. Cost Update Triggers
The system should recalculate BOM-based costs when:

Component material costs change
BOM quantities are modified
New components are added/removed from BOM
Labor rates or overhead percentages change
5. Manufacturing Cost Components
For complete cost accuracy, include:

Material Cost: Raw materials from BOM
Labor Cost: Process-specific labor rates
Overhead Cost: Factory overhead allocation
Scrap Allowance: Expected material loss percentage
6. Cost Freezing & History
Cost Freezing: Lock costs for active production orders
Cost History: Track cost changes over time
Cost Validation: Alert when calculated costs seem unrealistic
7. Integration Points
Purchase Orders: Use manual costs for purchased items
Production Orders: Use BOM-calculated costs for manufactured items
Inventory Valuation: Support both FIFO and weighted average with BOM costs
Job Work: Calculate expected costs vs actual costs
